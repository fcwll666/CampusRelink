# 连接与认证配置

CampusRelink 1.0.3 将用户名、密码、可编辑的登录 URL 和可选 Wi-Fi 连接放在「账户与连接」主界面。默认适配南京中医药大学，登录接口为 `http://net.njucm.edu.cn/api/portal/v1/login`。程序不提供「认证接口」配置页；请求格式、字段名、成功判定、联网检查和门户探测由程序内部处理。

## 搜索附近 Wi-Fi 与准备连接

点击主界面的「搜索 Wi-Fi」，程序会通过 Windows 原生 WLAN 接口，在运行本应用的电脑上异步扫描附近可见的无线网络 SSID。需要更新结果时，可再次点击搜索。发布包不携带开发机扫描的 SSID 列表，也不预置固定学校 Wi-Fi 名称。

打开界面时只读取 Windows 缓存中的网络信息与已保存配置，不主动扫描；只有明确点击搜索按钮才发起扫描。搜索结果中的附近未保存网络标注「请先在 Windows 连接」。如果希望应用自动连接该网络，请先在 Windows 网络设置中手动连接一次，让 Windows 保存配置文件及所需的无线网络密码，然后返回应用重新搜索。应用没有无线密码输入框；门户账号密码与无线网络密码用途不同，不要混填。

勾选「自动连接 Wi-Fi」后，必须选择具有有效 Windows 已保存配置的目标。配置文件名可能与无线网络 SSID 不同；仅能搜索到某个 SSID 并不代表已有连接凭据。应用不会猜测密码或为未知网络自动创建开放配置。

更新结果时保留仍有效的选择；没有有效选择时，只会在当前已连接的配置文件确实存在于列表中时预选它，不会自动选择第一个无关网络。没有搜索结果或无法读取 WLAN 状态时，可先通过 Windows 网络设置检查无线设备与网络连接。

取消勾选「自动连接 Wi-Fi」时，应用仅在当前网络上认证，不切换无线配置；可以使用有线网络或已由 Windows 手动连接的无线网络。

## 填写账号和登录 URL

在主界面填写学校提供的用户名、密码，并核对完整认证请求地址。默认南京中医药大学接口为：

```text
http://net.njucm.edu.cn/api/portal/v1/login
```

登录 URL 可直接编辑。其他学校需确认接口与内置协议一致；只更换地址不能适配不同协议。下面是不能用于实际认证的保留示例地址，可用于文档与模拟测试：

```text
https://portal.example.invalid/api/login
```

登录 URL 应由学校官方说明或网络管理员确认。URL 必须是绝对 HTTP 或 HTTPS 地址，不接受内嵌用户名密码、片段或换行；不要把账号、密码或身份令牌放入查询字符串。默认接口使用 HTTP，提交内容会经过未加密连接；如学校提供兼容的 HTTPS 地址，可在主界面修改并使用。

应用只保存一组用户名与密码，没有备用账号。保存后密码框显示固定 15 个星号 `***************`；这是占位提示，不是真实密码，也不代表密码长度。用户名不变且未修改占位提示或将密码框留空时，可沿用此前保存的密码；改变用户名时需要输入新密码。离线时使用这组账号认证，已经在线时保留当前连接。改名后仍使用 `%LOCALAPPDATA%\CampusFlowCommunity\` 与已有内部标识，继续读取此前社区版的本机配置和加密凭据。

## 如何获取认证接口

「登录 URL」应填写浏览器提交登录请求的接口地址。地址栏里的学校登录页面通常只是显示表单，不能直接当作认证接口。如果学校已经提供接口说明，优先以官方说明为准；需要自行确认时，可在自己的电脑上按以下步骤查看：

1. 先连接学校的校园 Wi-Fi 或有线网络，打开学校的网页登录页面。
2. 在登录页面填写自己的用户名和密码，先不要点击「登录」。
3. 按 `F12`，或在页面空白处右键选择「检查」，打开开发者工具，再选择 **Network / 网络** 标签。
4. 点击清空按钮，清除列表中的旧请求。若登录会跳转页面，可勾选 **Preserve log / 保留日志**。请求类型先保留 **All / 全部**；也可查看 **Fetch/XHR**，找不到时切回 All。
5. 保持开发者工具打开，再点击网页上的「登录」，查看这次操作产生的新请求。这一步会向学校提交自己的账号。
6. 找名称或路径含 `login`、`auth` 等字样的候选请求，点击查看详情。名称只是线索，还要确认它确实提交了登录数据；不要选图片、CSS、JavaScript 等静态文件、`OPTIONS` 预检请求，或只返回登录页面的 HTML 请求。
7. 在 **Headers / 标头（请求标头）** 的 **General / 常规** 区域找到 **Request URL / 请求网址**。这里显示的完整地址，就是要核对并填写到 CampusRelink「登录 URL」字段的认证接口。
8. 同时检查 **Request Method / 请求方法**、**Payload / 负载（请求正文）** 和 **Response / 响应**，与下方[内置认证行为](#内置认证行为)核对。本版本固定发送 POST JSON，字段为 `username`、`password`、`domain: "default"`，并按 JSON 响应的 `reply_code: 0` 判断成功。请求格式、字段或响应协议不一致时，仅修改 URL 不会自动适配。

以南京中医药大学为例，浏览器页面可能是 `http://net.njucm.edu.cn/portal/index.html?...`，其中 `...` 仅表示省略的网络参数；实际提交登录的 POST 接口是 `http://net.njucm.edu.cn/api/portal/v1/login`。应填写后者。不要复制他人页面中的完整查询参数、账号或 IP；也不要把请求正文粘贴到 URL 字段。

只需在本机查看这些信息，不必导出或分享完整 HAR。请求正文、Cookie、令牌和完整页面 URL 可能包含凭据或个人网络信息；需要求助时，只提供去敏后的请求方法、接口路径、字段名和响应结构。

## 内置认证行为

本版本只内置一种 Srun 风格的协议预设。应用向登录 URL 发送 HTTP POST，请求正文为 JSON，字段固定为：

```json
{
  "username": "demo-user",
  "password": "demo-password",
  "domain": "default"
}
```

响应需要是可解析的 JSON，且根对象中的 `reply_code` 为 `0`，例如：

```json
{
  "reply_code": 0,
  "message": "accepted"
}
```

HTTP 200 或显示成功网页不能代替此成功判定。请求错误、未知响应与认证拒绝会分别记录，供本机检查。该预设不保证兼容所有 Srun 部署、厂商或校园；不同协议需要修改代码适配，不能通过在界面里切换表单格式、字段名或额外参数解决。

联网检测向 `http://www.msftconnecttest.com/connecttest.txt` 发送不含账号密码的请求；仅 HTTP 200 且正文严格匹配 `Microsoft Connect Test` 时判定在线，不跟随重定向。HTTPS 登录 URL 仍正常验证服务器证书。认证与联网检查使用直接连接，不继承系统代理。应用根据登录 URL 在本机自动推导门户预取与代理探测地址；该推导基于内置预设，并非通用门户发现。认证前会尝试预取门户页面，与本次登录共享内存 Cookie；预取失败仍可继续提交认证。

## 启用与检查

确认输入后点击「保存并启用」，会保存配置、启动后台，并注册当前用户登录 Windows 后自动启动。首次打开界面本身不会创建自启。点击「停止后台」会停止后台并移除自启；关闭主窗口会收进托盘，托盘「退出」停止后台并结束程序，但保留自启。

「测试登录」会保存配置并向所填写的真实接口提交本机账号，不启用自启。失败时先核对学校提供的 URL 与内置协议是否匹配，再查看「运行日志」。分享日志或截图前检查其中的账号、Wi-Fi 配置名与网络信息。

## 开机阶段的遗留代理修复

这个功能针对一种常见的开机问题：上次关机前，VPN 或代理客户端没有正确退出或还原 Windows 手动代理；下次开机时，Windows 仍指向本机代理端口，但客户端尚未启动或该端口已经没有监听。浏览器等遵循系统代理的程序可能因此打不开校园登录页，表现为认证页面无法访问或登录流程受阻。

在主界面可按需勾选「开机时检查遗留的无效本机代理」。它按代理配置和端口状态判断，不按软件名称判断，也不保证适用于所有 VPN。它只处理 Windows 中已启用、且所有地址都是回环地址（如 `127.0.0.1`、`localhost` 或 `[::1]`）的手动代理；远程代理、仅使用 PAC 的配置，以及 TUN / 虚拟网卡等其他连接问题不在此修复范围内。

修复需要同时满足以下条件：

- 已保存有效的连接配置，并在自启后台入口启用了该选项。检查必须在可确认的实际开机后前 5 分钟内开始，每次开机最多一次，单轮最多持续 1 分钟。冷启动和快速启动可进入检查；休眠恢复不开放新的检查机会。
- 手动代理的所有本机端口在每次复查时都没有监听，代理配置也始终未变；发现有监听、状态无法确认、后台已停止或本轮检查超时，都会保留设置。
- 本轮前三次通过系统代理访问门户的探测连续发生传输失败。每次之间等待 5 秒；任何一次收到 HTTP 响应（包括错误状态码），或结果不确定，都会保留设置。这三次是门户可达性探测，不会提交账号密码，也不是三次认证失败。
- 最终复查通过，并成功写入 `%LOCALAPPDATA%\CampusFlowCommunity\startup-proxy-backup.xml`；备份之后、真正写入系统之前还会再次检查设置与端口。

满足条件后，程序关闭手动代理开关，启用直连与自动检测，保留代理地址、绕过列表和 PAC 等其他配置。没有可修复代理或代理正常也会消耗本次开机的检查机会；运行中的断网重连、手动「测试登录」或应用内重新启用后台不会触发这项修复。

CampusRelink 的认证请求、门户预取和联网检测本身使用直连，不继承系统代理；只有上述专用修复探测会显式使用系统代理。修复是为恢复受遗留代理影响的系统访问环境，并非所有认证请求都需要先修复代理。无法确认开机时间、备份失败或检查异常时，会保留代理并继续直连认证。

## 适配边界

默认接口针对南京中医药大学；内置预设不保证兼容所有 Srun 部署、厂商或校园。验证码、网页脚本执行、扫码、浏览器会话登录、动态挑战加密、专有签名和多步骤交互都需要另外实现协议适配并添加模拟测试，再由使用者在自己的网络中验证。发布包不包含真实账号、个人配置或开发机 SSID 列表；CI 只使用模拟环境，不进行真实校园登录或网络设置操作。
